# CS-300: Data Structures and Algorithms - Analysis and Design

Module Eight Journal Reflection

What was the problem I was solving in the projects for this course?

In CS 300, the main problem I was solving involved analyzing and implementing data structures to efficiently manage and organize course information. In Project One, I evaluated the runtime and memory usage of vectors, hash tables, and binary search trees to determine which structure best met the requirements. In Project Two, I implemented working code that could load course data, sort it alphanumerically, and print it cleanly for users. Together, these projects focused on choosing and applying the right data structures to solve real-world organizational problems. 

How did I approach the problem?

I approached the problem by first understanding the strengths and weaknesses of each data structure. Data structures are essential because they directly affect performance, scalability, and how easily information can be accessed or modified. I compared operations like insertion, searching, and sorting across the vector, hash table, and tree to determine which structure aligned best with the project's goals. This helped me make informed decisions when designing and implementing the final solution.

How did I overcome any roadblocks I encountered?

When I hit a roadblock, whether it was understanding how a structure handled collisions, figuring out traversal logic, or debugging sorting issues, I broke the problem down into smaller steps. I revisited examples, reviewed my pseudocode, and tested small pieces of logic before combining them into the full program. This incremental approach made it easier to identify mistakes and correct them without becoming overwhelmed. 

How has my work on this project expanded my approach to designing software and developing programs?

Working on these projects strengthened my ability to design software with intention rather than guesswork. I learned to evaluate multiple solutions before choosing one and to justify my decisions based on performance considerations. It also reinforced the importance of planning, writing pseudocode, analyzing structures, and mapping out how data flows through the program before jumping into coding.

How has my work on this project evolved the way I write programs that are maintainable, readable, and adaptable?

These projects pushed me to write cleaner, more organized code. I focused on separating logic into functions, using meaningful variable names, and structuring the program so future changes would be easy to implement. Understanding how data structures behave helped me design programs that are not only functional but also scalable and adaptable. I now think more about long-term maintainability instead of just making the code "work."
